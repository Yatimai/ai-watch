## 🔬 Research

### TeleChat to Xing4: Advancing Frontier Agentic Models on Domestic Chips and Frameworks
**147 upvotes** · Xingchen AGI Lab · [Paper](https://huggingface.co/papers/2611.22115)

Xing 4 is a 285B-parameter LLM series trained entirely on 8,192 Ascend 910C NPUs using Huawei's MindSpore stack, covering architecture choices (sparse MoE, speculative decoding), pretraining at scale, and a new post-training platform called TeleGym for agentic workloads. The paper is notable as a rare end-to-end account of frontier-scale training on non-NVIDIA hardware, with detailed engineering on topology-aware sharding and memory management. For teams watching the Chinese domestic chip ecosystem (Ascend 910C, MindSpore), this is one of the most concrete public disclosures to date.

### AscendGYM: A Cost-Aware Kernel Optimization Benchmark for Real-World Workloads on Ascend NPUs
**91 upvotes** · AI Training Platform Team · [Paper](https://huggingface.co/papers/2611.17621)

AscendGYM provides 48 kernels at three difficulty levels, with test cases derived from real LLM training/inference shapes on Ascend NPUs, so benchmark gains directly translate to production speedups. It introduces the **Speedup-Token Score (STS)** metric, which jointly penalizes token cost and rewards throughput improvement — a practical fit for evaluating agentic kernel-optimization loops. This pairs naturally with Xing 4 above, hinting at a broader push to build a full optimization toolchain around Ascend. The benchmark and harness are [open source](https://github.com/SLAI-AITP/AscendGYM).

### Weight-Space Programming Doesn't Need Transformers
**41 upvotes** · Hyunjong Ok, Jaeho Lee · [Paper](https://huggingface.co/papers/2611.22055)

When an LLM writes model weights directly (no gradient descent), the design constraints that made Transformers dominant no longer apply — and given free rein, frontier LLMs consistently converge on a sparse lookup-table architecture instead. That LLM-designed model reaches 54.4% test accuracy on multiple-choice tasks with ~1,800× fewer parameters than the best Transformer the same LLM produced. The proposed associative-memory architecture is also up to 17× faster on GPUs at equivalent size. A thought-provoking result for anyone thinking about weight generation, model compression, or the long-term relevance of the Transformer inductive bias.

## 📡 Analysis

### Quoting Daniel Stenberg (on AI-driven curl rewrites in Rust)
*2026-11-18* · [Post](https://simonwillison.net/2026/Nov/18/daniel-stenberg/) · tags: `curl`, `rust`, `coding-agents`, `security`, `vibe-porting`

curl's creator Daniel Stenberg points out that while AI agents spent ~3 weeks converting 185,000 lines of C into 340,000 lines of Rust, the actual curl project merged 300+ commits including ~200 bugfixes and several security patches — none of which made it into the AI-generated clones. The punchline is a sharp one: "Will these clones keep up?" It's a concrete reminder that "vibe-porting" large codebases produces a frozen snapshot, not a living project, and that correctness and security drift are immediate problems, not theoretical ones.

### External sandboxes for coding agents
*2026-11-17* · [Post](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/) · tags: `sandboxing`, `security`, `coding-agents`, `webassembly`, `claude-code`

Simon Willison (with Prime Radiant) proposes the **external sandbox** pattern: the agent lives outside the sandbox while only the code it executes runs inside an isolated VM, preventing prompt injection or mistakes from damaging the host machine. Three reference implementations are released covering WebAssembly/v86, Apple Containers, and Microsoft's Quicksand/QEMU bundle — all exposing the same localhost API for compatibility with Pi, Claude Code, and Codex. A built-in HTTP allow-list proxy and credential-replacement mechanism let you control network access and avoid leaking secrets to the agent, making local model experimentation meaningfully safer.
