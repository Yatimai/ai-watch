## 🔬 Research

### Demystifying Agent Skills: Why They Work—Until They Don't
**149 upvotes** · Jiang, Huang, Xing et al. · [Paper](https://huggingface.co/papers/2608.14036)

A large-scale controlled study of LLM agent "skills" (structured knowledge packages used at inference time) across 8,135 trial records and 12 identified skill-use modes. The key finding: skills mostly work by providing **procedural anchoring** (stabilizing noisy execution, 65.7% of cases), not by injecting missing facts (only 4.5%). Skills beat Workflow Memory by 6.06 points on average, but retrieval degrades sharply as pool size grows—precision collapses from 29.6% (5 skills) to 3.3% (100 skills). Critical reading for anyone building self-evolving agent pipelines.

### Agentic ESOpt: Fine-Tuning Long-Horizon LLM Agents with Minimal GPU Requirements
**96 upvotes** · Zheng, Chen, Ba et al. · [Paper](https://huggingface.co/papers/2608.17310)

Proposes replacing RL with **evolution strategies (ES)** for fine-tuning LLM agents on long-horizon tasks. ES only needs inference-level GPU memory (no backpropagation), handles sparse rewards better through trajectory-level attribution, and composes naturally with prompt-space optimization. On WebArena-Lite, full-parameter tuning of Qwen-3.5-27B improves the baseline by +6.69%. This matters because it makes fine-tuning large agentic models tractable without multi-GPU RL infrastructure.

### Zetta ζ: An Efficient Closed-Loop Embodied Harness for Self-Evolving Physical Intelligence
**84 upvotes** · Ding, Mi, Huang et al. · [Paper](https://huggingface.co/papers/2608.16590)

Zetta is a robotics harness that evolves **code-based critics and recovery skills online** during execution, across three time-separated loops (action-frequency, rollout-level, validation-gated), while keeping the base policy frozen. It achieves 90.8% on LIBERO-Pro and 93.6% on RoboCasa with an **11.1× inference speedup** vs. baselines, and learned skills transfer zero-shot. The key advance is genuinely closed-loop adaptation during physical execution—not just post-episode reflection—which is a meaningful step toward robust real-world robot autonomy.

### smolmachines / smolvm as a sandbox for untrusted Python & JavaScript
*2026-08-19* · [Post](https://simonwillison.net/2026/Aug/19/smolmachines-untrusted-sandbox/) · tags: sandboxing, coding-agents, llms, github-actions

Simon tasked Claude Fable 5 (via Claude Code for web) to stress-test [smolvm](https://smolmachines.com) as a secure sandbox for untrusted code. When the Claude Code environment lacked KVM support, the agent autonomously pivoted to running the full test battery via GitHub Actions—a notable example of agentic problem-solving under environmental constraints. Results: cold starts ~0.6–1.5s, warm executions ~50ms, with CPU/RAM limits, no-network execution, and filesystem isolation all working correctly. Practically useful for anyone building coding agents that need to run user-supplied code safely.

### Conceptual integrity and counting lines of code
*2026-08-19* · [Post](https://simonwillison.net/2026/Aug/19/conceptual-integrity-and-counting-lines-of-code/) · tags: ai, coding-agents, llms, podcast-appearances

From a Talking Postgres podcast appearance, Simon argues that **lines of code is actually a meaningful productivity metric** in the agent era—since a ceiling of ~200 LOC/day for a human engineer is a real constraint, and agents can push that to ~1,000 debugged LOC/day for skilled users. The flip side: the new bottleneck is **cognitive capacity**, not typing speed, so teams still scale. He also warns that agent-assisted development degrades "conceptual integrity" (from *The Mythical Man-Month*)—software accretes features in odd directions, like the Winchester Mystery House, because it's too easy to ship without architectural discipline.
