### Apodex 1.1: Scaling Agentic Intelligence for Complex Work
**177 upvotes** · Apodex Team · [Paper](https://huggingface.co/papers/2608.23283)

Apodex 1.1 is a 35B-parameter agentic system designed for "working capability" — sustained, verifiable progress on real-world tasks requiring files, search, code execution, and multi-agent coordination. It introduces two scaling axes: broader executable environments (Environment Scaling) and better task decomposition/replanning (Agentic Coordination Scaling), unified under an AgentOS layer for state and provenance tracking. The locally-deployable Mini variant makes this practically relevant for engineers wanting capable on-prem agents.

### EchoWM: Open and Enterable Omnimodal World Models
**66 upvotes** · Songchun Zhang et al. · [Paper](https://huggingface.co/papers/2608.23189)

EchoWM is an omnimodal world model that generates 720p video alongside synchronized environmental audio, music, and speech, while responding to continuous camera navigation in both first- and third-person perspectives. Navigation is unified via a shared metric-scale 6-DoF trajectory representation, avoiding the need for view-specific controllers. It advances the usability of generative world models beyond passive video generation toward interactive, navigable media — relevant for game simulation, VR, and embodied AI training data. The "enterable" framing positions it as a step toward persistent, explorable synthetic environments.

### Annotations as Rollouts: Efficient and Scalable RL for Video MLLMs (OraRL)
**65 upvotes** · Yunheng Li et al. · [Paper](https://huggingface.co/papers/2608.20492)

OraRL improves RL post-training for video multimodal LLMs by treating existing human annotations as "oracle rollouts" — positive optimization targets injected directly into the on-policy training group — rather than just reward signals. A key technical contribution is the decoupled advantage estimator that avoids "advantage inversion" when a high-reward oracle skews the group baseline. The result: only 2.2× the step time of SFT (vs. 4.9× for GRPO with CoT), and Video-ORA-9B scores 73.1 on VSI-Bench against 55.0 for GPT-5 and 55.1 for Gemini-3-Pro, while decoding in 130 ms instead of 4,780 ms. A meaningful efficiency-vs-performance win for anyone fine-tuning video models at scale.

### EVE Online: The Move to Python 3 Begins!
2026-08-25 · [Post](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) · tags: `eve-online`, `migrations`, `python`, `python3`, `stackless`

EVE Online has run on Stackless Python since 2003 — last upgraded to Stackless 2.7 in 2010 — and is now finally migrating its 2.4 million lines of code to Python 3 using `futurize`, with manual review of ~20,000 behavioral divergence points (e.g. integer division). What's not yet addressed publicly is the Stackless replacement, though their newer game EVE Frontier already solved this with an open-source `carbonengine/scheduler`. A rare, at-scale case study in legacy Python migration that's directly applicable to anyone maintaining large Python 2-era codebases.

### Your executable is a SQLite database
2026-08-24 · [Post](https://simonwillison.net/2026/Aug/24/your-executable-is-a-sqlite-database) · tags: `c`, `linux`, `sqlite`

Farid Zakaria describes a technique for encoding an ELF binary's components (code, data, metadata) into SQLite tables, then using SQLite's 4-byte application ID field to mark the file as a `SELF` (Structured Executable & Linkable Format) executable. A custom `self-exec` interpreter extracts and runs it, and Linux's `binfmt_misc` mechanism can automate this transparently at the kernel level. Niche but conceptually interesting: it turns a SQLite database into a first-class executable format, opening the door to using SQL queries to inspect, patch, or version-control binary assets.
