## 🔬 Research

### Kandinsky 6.0 Video: Foundation Models for Synchronized Video and Audio Generation
**103 upvotes** · Team Kandinsky · [Paper](https://huggingface.co/papers/2610.05608)

Kandinsky 6.0 Video introduces two open-source diffusion models — a 3B "Lite" and a 29B "Pro" — that natively generate 5-second Full-HD clips with synchronized 44 kHz audio and lip-sync, in both text-to-AV and image-to-AV modes. The architecture uses a dual-stream CrossDiT connecting a pretrained video stream and a new audio stream via bidirectional cross-attention, trained with a staged curriculum (pretraining → SFT → RLHF → distillation). In human side-by-side evals, the Pro model outperforms Kandinsky 5.0 Video Pro and stays competitive with leading closed models on speech quality. Code, checkpoints, and Diffusers integration are released under MIT — a rare fully open multimodal AV generation stack at this scale.

### ALoDLM: Adaptively Looped Diffusion Language Models
**41 upvotes** · Liancheng Fang et al. · [Paper](https://huggingface.co/papers/2610.04198)

ALoDLM addresses the "computation-difficulty mismatch" in diffusion language models: instead of applying the same compute depth to every token at every denoising step, it uses token-adaptive latent recurrence — easy tokens are committed early, while hard tokens get additional refinement passes. Trained at 1.7B and 8B scales, ALoDLM outperforms all evaluated DLMs *and* autoregressive baselines across 11 benchmarks, while retaining parallel decoding speed. This is a meaningful step toward closing the quality gap that has kept diffusion LMs from replacing autoregressive models in practice.

### MemAdapter: Counterfactual Adaptation Against Memory-induced Sycophancy
**23 upvotes** · Ruqing Ning et al. · [Paper](https://huggingface.co/papers/2610.05162)

Long-term memory in LLM agents can cause sycophancy even when memories are *factually correct*, because agents over-weight prior user beliefs relative to current evidence. MemAdapter counters this with three components: counterfactual induction (surfacing a memory's potential bias), context-aware reflection (calibrating each memory's influence per task), and evidence-based reasoning (grounding the final answer appropriately). Evaluated on three benchmarks, it consistently improves memory reliability across diverse scenarios. Code is available at [github.com/DEEP-JLU/MemAdapter](https://github.com/DEEP-JLU/MemAdapter).

### Claude Cowork moves VM execution to the cloud
*5 Oct 2026* · [Post](https://simonwillison.net/2026/Oct/5/felix-rieseberg/) · tags: `claude-cowork`, `anthropic`, `claude`, `general-agents`

Felix Rieseberg (Anthropic) announced that Claude Cowork's architecture has shifted: model inference and the sandboxed VM now run fully in the cloud rather than locally on users' machines, with the desktop app handling only device-level file access tool calls. This directly addresses user complaints about battery drain, disk usage, and work stopping when the laptop closes — and also enables Cowork from a phone. It's a significant signal that general-purpose cloud-side agent execution with selective local delegation is becoming the production deployment pattern for serious AI agents.

### Qwen3.8 27B struggles with large-number addition in words — until reasoning is enabled
*4 Oct 2026* · [Post](https://simonwillison.net/2026/Oct/4/qwen38-addition-in-words/) · tags: `qwen`, `llm-reasoning`, `local-llms`, `mathematics`

Simon Willison replicated Colin Frasier's "add numbers and return the answer in English words" benchmark on a local DGX Spark using `Qwen3.8-27B-Q4_K_M.gguf`. Without reasoning, accuracy collapses from 97% on small numbers to 6.4% on 10–13 digit operands (23.6% overall). With reasoning enabled, the model scored 167/169 — near-perfect — by explicitly performing column-by-column arithmetic in its chain of thought. This neatly demonstrates that reasoning traces can substitute for tool-use when handling structured computation, but only if the model is given the compute budget to use them.

### We need default hard budget caps on everything — and it's finally happening
*3 Oct 2026* · [Post](https://simonwillison.net/2026/Oct/3/default-hard-budget-caps/) · tags: `amazon-web-services`, `ai`, `coding-agents`

Simon argues that as coding and personal agents spin up pay-per-use services on users' behalf, hard spending caps must become the *default* on all cloud platforms — not opt-in email alerts, but enforced cutoffs. The good news: AWS quietly launched project-level spend limits in September 2026, and Google Cloud introduced Spend Caps in July 2026, suggesting the industry is moving in this direction under pressure. For AI engineers deploying agents that provision infrastructure, this is a timely reminder to verify hard caps are configured before going to production.
