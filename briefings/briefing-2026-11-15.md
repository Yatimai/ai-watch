## 🔬 Research

### SO-Arena: Benchmarking the Capability Spectrum and Reliability of System One Models
**136 upvotes** · Lichen Li et al. (NUS) · [Paper](https://huggingface.co/papers/2611.15777)

SO-Arena benchmarks "System One" models — fast, non-chain-of-thought decision-making models — across 11 domains and 5 capability families, covering both accuracy and **decision reliability**. Reliability is measured along two axes: stability under option-set permutations, and ability to recognize when no valid answer exists. Key finding: the top-performing model overall ranks only **7th** in reliability, decoupling raw accuracy from trustworthy decision-making. Useful reference for teams deploying fast-inference models in production settings where consistency matters as much as performance.

### BirdDreams: Joint Perspective and BEV Video Generation for a Plausible, Reactive Driving World Model
**50 upvotes** · Junyoung Seo et al. (Seoul National U. / TU Munich) · [Paper](https://huggingface.co/papers/2611.14815)

BirdDreams is an autoregressive driving world model that simultaneously generates first-person perspective video and a bird's-eye-view (BEV) schematic video, with two diffusion transformers attending jointly to each other's stream. The BEV acts as a geometric interface for ego-trajectory control — no HD map or vehicle-state inputs required at inference, only a single camera image. On PhysicalAI-AV and nuScenes, it outperforms prior models on ego-trajectory fidelity and surrounding-vehicle realism. This matters for autonomous driving simulation pipelines that need reactive scene generation without expensive annotation of future vehicle trajectories.

### Scaling Mathematical Proof Supervision from Structured Textbooks
**47 upvotes** · Youqing Fang et al. · [Paper](https://huggingface.co/papers/2610.40394)

TOME-Math converts **2,118 university-level math textbooks** into ~380K structured proof-supervision records, preserving chapter order, proposition-proof links, and dependency references — rather than flattening everything into isolated Q&A pairs. Fine-tuning on TOME-Math yields a **+16.7 percentage point** improvement on held-out math benchmarks vs. the base model, beating all three public instruction-data baselines. The corpus will be released publicly, making it a potentially significant resource for training math-reasoning LLMs with curriculum structure rather than raw problem dumps.

## 🛠 Tools

### GoogleChrome/modern-web-guidance-src — Inject modern web best practices into coding agents
**1,220 stars/day** · 6,755 total stars · [Repo](https://github.com/GoogleChrome/modern-web-guidance-src)

A set of "skills" (structured guidance files) that embed up-to-date web platform knowledge, best practices, and browser compatibility data directly into coding agents' context. Stewarded jointly by **Google Chrome, Microsoft Edge, Mozilla Firefox, and MDN**, so the guidance reflects cross-browser consensus. Install with `npx modern-web-guidance@latest install`; it also includes a codebase scanner to flag legacy patterns. Directly addresses the well-known problem of AI coding agents generating outdated or compatibility-breaking web code.

### dream-num/univer — Open-source AI office SDK (spreadsheets, docs, collaboration)
**1,041 stars/day** · [Repo](https://github.com/dream-num/univer)

Univer is an extensible TypeScript SDK for embedding spreadsheet editing, calculation, real-time collaboration, and file processing into your own product — for both human users and AI agents. Think "open-source Google Sheets/Docs core" that you can wire up with AI pipelines. The "AI office" framing targets teams building agentic workflows that need programmatic document and calculation capabilities without locking into SaaS APIs.

### backnotprop/plannotator — Human-in-the-loop annotation workspace for AI agents
**860 stars/day** · 11,626 total stars · [Repo](https://github.com/backnotprop/plannotator)

Plannotator is a workspace for staying in control of AI coding agents: it surfaces agent plans, specs, diffs, and PRs in a reviewable inbox, lets you annotate markdown/HTML artifacts, and sends consolidated feedback back to the agent in one click. It supports all major agent CLIs — Claude Code, Codex, Copilot, Gemini CLI, Amp, Kiro, and others. With 11K+ stars, it has traction as a practical answer to the "agent runs off unsupervised" problem for teams working with autonomous coding agents.

## 📡 Analysis

### datasette-llm 0.1a11
2026-11-14 · [Post](https://simonwillison.net/2026/Nov/14/datasette-llm/) · tags: `llm`, `datasette`, `generative-ai`, `uv`, `datasette-agent`

The key addition in this release is **OpenAI-compatible endpoint support**, meaning Datasette can now be backed by any locally-hosted model (LM Studio, Ollama, llama.cpp v1.0) without code changes. The example in the post shows running a full Datasette Agent instance powered by Qwen 3.8 27B locally via `uvx` — no cloud API key needed. This makes the datasette-agent ecosystem viable for air-gapped or cost-sensitive deployments.

### datasette-vega 0.7
2026-11-14 · [Post](https://simonwillison.net/2026/Nov/14/datasette-vega/) · tags: `datasette`, `visualisation`, `datasette-lite`

After **8 years without a release** (last update: July 2018), datasette-vega gets a compatibility bump for Datasette 1.0 alphas and now works with Datasette Lite — the browser-based, serverless version of Datasette. The notable underlying change: Datasette Lite just gained the ability to run JavaScript plugins, opening the door to richer in-browser data tooling. Low-drama release, but signals ongoing momentum in the Datasette ecosystem's WebAssembly direction.
