## 🔬 Research

### MemT-1.0: Towards Memory-Native Evolution
**128 upvotes** · Zhiyu Li, Zeyu Zhang et al. · [Paper](https://huggingface.co/papers/2610.26825)

MemT-1.0 is a new architecture that treats memory as an intrinsic part of model computation rather than an external add-on (like RAG), using Gated DeltaNet-2 and a "Mixture-of-Storage" mechanism to scale native memory capacity. Two model sizes are released — MemT-1.0-Nano and MemT-1.0-Flash — trained on 34B tokens. The efficiency gains are significant: at 128K history length, MemT-1.0-Nano is ~1.86× faster end-to-end and reduces persistent storage by 66× vs. full KV cache. This is a practical alternative to full context caching for long-horizon agentic tasks.

### BrainLoRA: Scaling Parameter-Efficient Fine-Tuning for Brain Encoding
**94 upvotes** · Zhuofan Josh Ying, Guanglong Sun et al. · [Paper](https://huggingface.co/papers/2610.26802)

Brain encoding models predict neural responses to stimuli, and this paper shows that LoRA adapters can fine-tune multimodal backbones up to 104B parameters for this task — the largest brain encoding model to date — despite the scarcity of neural data. A multi-LoRA kernel enables joint training of 200+ adapted models, and the resulting ensemble ranks **#1 on the public Algonauts 2025 post-challenge leaderboard**. Beyond neuroscience, this validates PEFT as a go-to paradigm when labeled data is limited and backbones are large.

### Learning from Fleet Experience: Collective Learning for Robot Fleets
**93 upvotes** · Chao Yu, Shu'ang Yu et al. · [Paper](https://huggingface.co/papers/2610.25736)

This paper introduces Collective Experience Learning (CEL), where deployed robots share successful execution traces to improve a shared policy — without requiring human teleoperation corrections. Their system FERT uses failure contexts to retrieve relevant successful trajectories as supervision, coordinated via a fault-tolerant async training system (FATS). Results across 5 real manipulation tasks show 93.3–99.2% success rates; scaling from 1 to 96 robots on a phone-packaging task boosts success from 79.2% to 98.3%. This is a compelling path toward self-improving robot fleets that don't need growing armies of human supervisors.

## 🛠 Tools

### MadsLorentzen/ai-job-search — Local AI job application framework
**3,890 stars/day** · [Repo](https://github.com/MadsLorentzen/ai-job-search)

A Python framework built on Claude Code that automates the job search pipeline: evaluating postings, tailoring CVs, writing cover letters, and preparing for interviews — all running locally on your own machine with your own API subscription. The "fork it and own it" philosophy means no SaaS intermediary storing your resume data. The explosive star count suggests it struck a nerve at a time when AI-assisted job hunting is becoming table stakes.

---

### stablyai/orca — Multi-agent coding runner
**1,559 stars/day** · [Repo](https://github.com/stablyai/orca)

Orca is a desktop/mobile/remote interface for running a fleet of coding agents (e.g., Grok Bot, Claude Code) using your own API subscriptions, in TypeScript. It abstracts the orchestration layer so engineers can run multiple coding agents in parallel without vendor lock-in. The "bring your own subscription" model is a direct answer to the cost concerns of managed coding agent platforms.

## 📡 Analysis

### My obituary for programming
*2026-10-19* · [Post](https://simonwillison.net/2026/Oct/19/my-obituary-for-programming/) · tags: `programming`, `careers`, `ai`, `coding-agents`, `llms`

Simon links to a piece by Jeremy Scheff that articulates the specific loss coding agents represent for programmers who found intrinsic joy in the *puzzle* of writing code — not just in shipping software. The key distinction: if you love *building systems*, LLMs are a superpower; if you loved *solving the logic puzzles themselves*, that satisfaction is being automated away. A useful framework for engineering teams thinking about retention and morale in the age of coding agents.
