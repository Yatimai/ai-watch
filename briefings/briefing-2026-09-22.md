### EvoOntology: A Self-Evolving Ontology Layer for Data Agents
**126 upvotes** · Meiduo Chong, Shaolei Zhang, Ju Fan, Xiaoyong Du · [Paper](https://huggingface.co/papers/2609.15779)

Data agents struggle when facing large, heterogeneous data sources (tables, files, databases) because they can only interact through generic tools, creating an "agent-data gap." EvoOntology addresses this by wrapping data knowledge into an MCP server with schema, content, and tool layers, allowing agents to query it at runtime. A builder agent autonomously constructs and continuously refines this ontology via attribution-guided edits, validated through a paired evaluation protocol. Tested on three benchmarks with four LLM backbones, it consistently outperforms both raw-exploration and static semantic-layer approaches — with code available at [github.com/ruc-datalab/EvoOntology](https://github.com/ruc-datalab/EvoOntology).

### CodeMidas: Scaling Agentic Coding RL Environments from Code Itself
**103 upvotes** · Bowen Ye, Lei Li, Shicheng Li, Zihao Yue, Linghao Zhang · [Paper](https://huggingface.co/papers/2609.22068)

RL training for coding agents is bottlenecked by the scarcity and narrow diversity of high-quality tasks — CodeMidas fixes this by extracting executable RL environments directly from existing open-source codebases, requiring only source code as input. The resulting dataset covers 5,545 training tasks across 3,185 codebases, 23 languages, and 15 technical domains. Fine-tuning MiMo-V2.5 with GRPO on these tasks delivers meaningful gains: +11.7% on DeepSWE, +17% on ProgramBench, +8.5% on Terminal-Bench v2.1. The key finding is that source code itself is a scalable, largely untapped foundation for building diverse coding agent benchmarks.

### Transferring the Intelligence of VLMs to Robotic Control
**93 upvotes** · Meng-Hao Guo et al. · [Paper](https://huggingface.co/papers/2609.22966)

RoboDawn tests whether off-the-shelf VLMs can control robots without any task-specific training, by exposing a compact interface of discrete translation, rotation, and gripper commands as an agentic loop. In zero-shot conditions it already beats several policies trained on benchmark-specific robot data; adding just one in-context demonstration pushes success rates from 53.2% to 73.6% on RoboTwin 2.0 C2R, exceeding the strong π0.5 baseline (46.0%). Similar gains appear on RoboDojo and on real Franka robots. This matters because it suggests VLMs carry transferable physical reasoning, dramatically lowering the data cost of robotic deployment.

## 🛠 Tools

### google/ax — Declarative orchestration runtime for autonomous agent workloads
**2324 stars/day** · [Repo](https://github.com/google/ax)

AX is Google's open-source, Kubernetes-inspired orchestrator for running agent workloads at cluster scale, built on top of `agent-substrate/substrate` for sandboxed execution. It provides four primitives — `Task`, `Workspace`, `Gateway`, and model config — covering isolation, pre-wired Git repos/MCP servers, network fencing, and cost controls. With 6,808 total stars and active development (last push Sept 20), it is still pre-stable with breaking changes expected. Engineers building multi-agent pipelines at scale will want to watch this closely as a potential production-grade alternative to rolling their own orchestration.

---

### agent-substrate/substrate — High-density sandbox runtime for agent workloads
**498 stars/day** · [Repo](https://github.com/agent-substrate/substrate)

Agent Substrate is the low-level execution layer underlying `google/ax`: a secure-by-default runtime that multiplexes many agent "actors" onto fewer workers, exploiting the fact that agents are mostly idle. It claims 10× higher density than standard container runtimes, sub-500ms resume latency, and >500 suspend/resume ops/second, with support for microVMs and gVisor. Notably flagged as *not* an official Google product and not covered by Google's vulnerability rewards program. Useful independently of AX for any team needing efficient, zero-trust isolation for large fleets of agents.

**436 stars/day** · [Repo](https://github.com/anthropics/financial-services)

## 📡 Analysis

### Jev introduces a new shape of LLM — System One, aka Decision Models
*21 Sep 2026* · [Post](https://simonwillison.net/2026/Sep/21/jev/) · tags: `ai`, `generative-ai`, `llms`

TypeSafe AI's **Jev** takes text in but outputs typed probabilistic decisions (yes/no, choice, score) rather than free text, making it purpose-built for classification tasks like spam detection, ranking, and labeling. It's priced at $0.042/million input tokens (output is free), cheaper than GPT-5 Nano, and evaluates multiple questions against a document in parallel. Simon finds the "decision model" framing more accurate than "System One model" and flags a concern: like older ML classifiers, Jev offers no chain-of-thought, making it a black box again — a regression in interpretability that practitioners should factor in.

### Quoting voxium — Claude Code as the only author in a large engineering org
*20 Sep 2026* · [Post](https://simonwillison.net/2026/Sep/20/voxium/) · tags: `ai-misuse`, `llms`, `ai`, `generative-ai`

A viral anecdote describes an engineer joining a large company where every artifact — specs, code, tests, PRDs, tickets, reports — is generated by Claude Code, with engineers spending 12–13 hour days doing little more than hitting Enter. Management perceives no shipping bottleneck while engineers report no one reads or understands what is being produced. This is a sharp, ground-level data point on AI-induced output theater: velocity metrics look fine while comprehension, ownership, and accountability quietly disappear — a systemic risk that tool-adopting teams should actively design against.
