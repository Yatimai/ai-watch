### Don't Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents
**64 upvotes** · Yukyeong Lee et al. · [Paper](https://huggingface.co/papers/2611.14320)

LLM agents that learn from past experience via distilled memory "lessons" can paradoxically perform *worse* than agents with no memory at all — a phenomenon the authors call memory-induced degradation. WikiTrace addresses this by linking each lesson to a summary of *why* its source trajectory succeeded or failed, plus the raw trajectory itself, so the agent can fact-check and correct a lesson before acting on it. Evaluated on five agentic benchmarks, WikiTrace consistently outperforms existing memory approaches while reducing degradation cases. The code is available at [github.com/yukyeongleee/wikitrace](https://github.com/yukyeongleee/wikitrace).

### Tree-Ising: Repairing Language Models with Bit-Level Ising Edits
**50 upvotes** · Hadi Salloum, Ammar Ali · [Paper](https://huggingface.co/papers/2611.14210)

Tree-Ising reframes LLM weight repair as a sparse discrete optimization problem: instead of gradient descent or costly LLM agent turns, it frames each output row as an independent QUBO/Ising problem and solves it with GPU simulated annealing or quantum-inspired simulated bifurcation. On Qwen3.5-0.8B it reaches 54.6% on MATH-500 (vs. 51.7% for a GPT-6 agent edit and a 7.9% base), touching only 13–17% fewer weights, reducing BF16 bit-flips by ~2.2×, requiring zero LLM tokens, and costing ~$0.90 in GPU time. On Qwen3.5-2B, the same recipe jumps greedy GSM8K from 21.6% to 69.4%. As a proof of concept, an 8-variable sub-problem was run on a real IBM Heron quantum processor.

### One Table, Many Queries: Benchmarking Generalist Tabular Models Across Generation, Imputation, and Prediction
**37 upvotes** · Yuanrui Wang et al. · [Paper](https://huggingface.co/papers/2611.13001)

The **One Table Benchmark** covers 56 datasets, 46 methods, and 20 capability axes to rigorously compare tabular models across three typically siloed tasks: data generation, imputation, and prediction. Key finding: some generalist models already beat specialist portfolios on predictive utility, but distributional fidelity still favors specialization, and objective interaction effects are non-additive and backbone-dependent. Frozen foundation models show surprisingly strong prediction and imputation, hinting that large pretrained models are becoming practical drop-in tabular solvers.

## 📡 Analysis

### Gemini Decisions API
2026-11-11 · [Post](https://simonwillison.net/2026/Nov/11/gemini-decisions-api/) · tags: `ai`, `gemini`, `llm-release`, `decision-models`

Google launched **Gemini Decision 1**, entering a niche category of "decision models" alongside Jev and OpenAI's GPT-6 Luna, all designed to answer structured yes/no, choice, and rubric-scoring queries cheaply. Gemini's key differentiator is full multimodality (text, images, audio, video, PDFs), priced at $0.10/M input tokens (output free), versus Jev's cheapest-in-class $0.042/M. Notably, Gemini returns calibrated probabilities (e.g. 0.923) rather than the binary 1.0/0.0 of competitors — a subtle but meaningful difference for downstream decision pipelines.

### aws-emulator — Official AWS local service emulator
2026-11-11 · [Post](https://simonwillison.net/2026/Nov/11/aws-emulator/) · tags: `amazon-web-services`, `testing`, `rust`, `agentic-engineering`

AWS finally ships an official local emulator for testing against their services without a paid API key — something the community has long jury-rigged with tools like LocalStack. It's written in Rust and reportedly accumulated 29,684 commits in its first three weeks, built by a large swarm of AI agents. Currently requires Docker on macOS/Windows, which limits single-binary portability; Simon flags this as the main friction point for adoption in standard test suites.
